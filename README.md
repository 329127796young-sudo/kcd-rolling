# 墙洞酒馆 · Wallhole Tavern

一个无需构建工具的中世纪酒馆骰子博弈原型，按你提供的《天国拯救 2》规则页和实机截图重做，包含：

- 主界面：通过“寻找牌友”打开独立牌桌选择弹窗；支持免费练习桌和正式赌局，另有“我的骰盒”入口。
- 主页规则入口：主页不展示规则摘要，只保留“完整规则”按钮；热骰连火倍率在规则册中明确为 `x1 → x2 → x3 → x5 → x8 → x12`，第 5 次及之后封顶 x12。
- 货币系统：统一使用格罗申；默认钱包 100 格罗申。练习桌不扣本金，胜利固定奖励 5 格罗申；正式赌局基础赌注为 10 / 50 / 100 / 300 格罗申，进入正式牌局前必须准备基础赌注的 5 倍，玩家获胜或落败都按最终生效的公共牌桌倍率结算，不设 x2 亏损封顶。
- 倍率交互：加码申请整合在牌桌右下角倍率面板；提出加码时等待对手回应，收到挑战时直接在面板接受或拒绝，不使用中央加码弹窗。
- x5 反馈：正式牌局公共倍率确认达到 x5 后，右下角倍率面板显示低亮度烛火、暖色呼吸光和少量余烬；申请中、练习桌和重开状态不显示。
- 单机对战：七枚骰子、保留骰子、连续续掷、爆骰归零、普通/完美热骰与 AI 回合；活动中的剩余骰子显示在牌面，已保留骰子在选择后仍留在原位，点击再次投掷时才会收起并从下一掷碰撞中移除。每次再掷独立计算当前掷的组合，不会把上一掷的三同与下一掷单骰拼接计分。
- 对手差异：米洛偏稳健，瓦茨拉夫偏冒险，玛蒂娜是会做一步收益前瞻的账房型对手（领先封锁分差、落后时低风险追分），穆萨偏概率判断；每位对手有不同收集阈值、骰子组合和回合决策。AI 现在还会维护短期信心、压力、挫败、贪心和谨慎状态，记住玩家近期收分、爆骰与加码习惯，并在合法方案中产生有限的次优失误；思考时间会随风险、情绪和角色差异动态变化，右侧反应文本会跟随牌桌事件变化。每个 AI 回合还会根据连续续掷、热骰追逐与投掷次数触发理智边界，瓦茨拉夫可以更久地追分但不会无限投掷。胜负改为六回合比累计总分：六个大回合结束后，累计分更高者获胜；若总分相同则进入突然死亡，下一轮高分者立即获胜。这样高风险打法的超大回合收益会真正反映在最终结果中。
- 规则组合：1 点、5 点、三同、四/五/六同翻倍、小顺、大顺。
- 骰子库：玩家默认装备七枚普通骰子；内置特殊骰子及 1–6 点概率，可点击装备并影响实际投掷权重，也可随时使用“还原普通骰”恢复默认配置。
- 名片商店：收藏页分组展示三张对手胜利奖励名片、八张风景名片与八张“油画 DLC”名片；两组付费名片均可用格罗申购买，购买/装备状态分别写入 `wallhole-collection-v1` 与 `wallhole-wallet-v1`，不影响胜率。
- 骰子皮肤：顶部“骰子”入口提供独立的外观皮肤收藏与装备页；首发“墙洞酒馆 · 黑橡木铜箍”定价 120 格罗申。皮肤状态写入 `wallhole-dice-skins-v1`，只改变 3D 材质，不影响功能骰子权重、计分或 AI；当前黑橡木纹理由本地 CanvasTexture 生成，“我的骰盒”改为管理七个功能骰子槽位。
- 每日签到：主页“寻找牌友”左侧提供签到入口，每个本地自然日可领取 150 格罗申；连续签到 7 天自动解锁限定品质“纯银骰子”。签到状态写入 `wallhole-daily-checkin-v1`，断签只重置连续天数，不会收回已解锁外观；纯银骰子不出售，也不进入酒馆抽奖池。
- 规则页：通过牌桌右侧“查看规则”进入；骰子配置通过左侧“编辑组合”或主页“配置我的骰子”进入，包含基本规则、点数组合、骰子概率、保留/爆骰、获胜条件与牌桌提示。
- 联机大厅（第三阶段）：通过顶部“本地练习/联机大厅”入口打开真实本地 WebSocket 大厅；支持创建/加入 6 位房间码、开放牌桌列表、双方准备、房主开始、离开牌桌与断线座位保留。`shared/game-rules.js` 现在由 Node 房间服务器加载，服务器权威处理投掷随机、锁骰、计分、热骰、四回合轮转、倍率申请/回应和投降。访客身份使用浏览器生成并保存在 `wallhole-online-player-v1`，服务器在 `server-data/players.json` 维护统一的格罗申钱包、累计收支、名片/勋章/骰子皮肤收藏与最近结算；客户端启动时自动同步，单机和联机商店购买、装备及奖励写回同一份账户资料。联机练习桌胜者由服务器只发放一次 +5 格罗申；正式联机赌局目前只记录结算，不改动余额，待下一阶段接入明确押注规则。
- 牌桌界面：顶部仅保留“牌桌”状态入口；“返回主页”按钮固定在牌桌工具栏的高对比层级，不会被透明骰子画布遮挡。
- 默认棋盘：第一阶段使用 `assets/images/boards/tavern-oak/base.webp` 作为墙洞酒馆旧橡木桌面，并叠加独立的 `wear.png` 磨损层；中央骰子区保留透明 3D 画布，木桌材质位于其下方。
- 棋盘扩展：顶部“棋盘”入口已经接入主题选择菜单，旧橡木与贵族大厅·胡桃木可直接切换，城堡宴席仍为锁定占位主题；后续可在 `BOARD_THEMES` 与 `assets/images/boards/` 下追加主题资源。主题通过 CSS 变量切换主体纹理、磨损层和强调色，不需要改动骰子物理逻辑。
- 场景背景：主页当前使用 `assets/images/homepage-bg-03B-04B.webp` 作为 `03B.webp`（左）与 `04B.webp`（右）拼接后的横向中世纪插图背景；旧的 `homepage-bg-01-02.webp` 保留作为历史版本。牌桌场景使用 `assets/images/tavern-bg.svg`，原始图片统一保留在 `assets/images/` 便于后续检索。
- 图片资源统一放在 `assets/images/`，音频资源目录保留为 `assets/audio/`；当前背景音乐文件已移除以控制仓库体积，骰子音效由 Web Audio 实时合成。
- 三维骰子层：牌桌中央只使用 Three.js r128 在透明 canvas 上渲染木制骰子本身，`renderer.setClearColor(0x000000, 0)` 保证 2D 牌桌背景直接透出。骰子投射到 `THREE.ShadowMaterial` 地板（`opacity: 0.4`）的实时 PCF 软接触阴影，不再绘制独立木盒模型。
- 物理投掷组件：`dice-physics.js` 使用 Cannon.js 在透明 canvas 上模拟骰子。每位玩家固定七个可复用实体，下一掷只激活未锁定槽位，不会无限堆积 Mesh；骰子从靠近骰盅的集中位置带共同前进方向散开，不再从整张桌面凭空随机生成。骰子在接近桌面、仍处于下降阶段时提前完成目标朝向插值，落地准备完成后锁住该朝向，只让位置继续走物理，避免最后一次碰撞把预设点数转成另一个可见面，同时仍使用预先计算的权重结果。玩家 UI 也等待物理层完成落地回调后再提交本次点数，回退路径只用于 WebGL/物理层不可用的情况。锁定骰子在选择后保持可见，下一次投掷开始时才从牌面收起并暂时隐藏，同时移出碰撞，普通/完美热骰或新回合时由同一实体池重新显示。重力为 `-25`，骰子材质使用摩擦力 `0.5`、弹性系数 `0.3`；静止判定为速度 `0.11`、角速度 `0.12` 持续 `0.2s`。四面不可见高墙和地板按照牌桌框尺寸动态测量，另有越界安全围栏防止高能量帧把骰子带出牌桌。碰撞冲量会触发骨质 Web Audio 撞击声和轻微镜头震动，翻滚/滑动阶段增加节流的低音量摩擦噪声。蜡烛光和补光阴影贴图提升至 `1024×1024`。可通过 `window.DicePhysics3D.rollDice(count, targetValues, callback, options)` 投掷，并使用 `onDiceSelected`、`onDragRoll` 接收 3D 交互回调。
- 三维交互：鼠标悬停骰子时显示金色材质微光并切换指针；点击任意 3D 骰子都可通过 `onDiceSelected(diceId, value)` 锁定或解锁，不再要求当前组合先产生分数。零分组合仍可继续投掷并保持 0 分，由玩家自行承担选择结果；拖拽释放会把方向脉冲传给未锁定骰子。牌桌不再渲染 2D 骰子镜像，骰子只存在于透明 Three.js Canvas。
- 投掷反馈：骰盅过渡动画、骰子翻滚动画、可见的对手回合和键位操作提示（E 保留、F 保留并投掷、Q 收集、R 重开、T 规则）。

## 运行

直接打开 `index.html` 即可体验单机模式。若要测试本地联机大厅，请使用内置的无依赖 Node 服务（不要直接双击页面）：

```powershell
node server.js
```

然后访问 `http://127.0.0.1:4173/`，再打开顶部“联机大厅”。也可以运行本地协议回归测试：

```powershell
node tools/test_local_multiplayer.js
```

验证联机钱包结算与重连后的服务器存档：

```powershell
node tools/test_online_wallet.js
```

验证共享钱包、购买与装备在重连后保持一致：

```powershell
node tools/test_shared_profile.js
```

部署到公网服务器时，先把站点与 `server.js` 放在同一目录，再使用环境变量绑定公网网卡和数据目录：

```powershell
$env:WHT_HOST='0.0.0.0'
$env:WHT_PORT='4173'
$env:WHT_DATA_DIR='D:\wallhole-data'
$env:WHT_ALLOWED_ORIGINS='https://你的域名'
node server.js
```

服务器提供 `/healthz` 健康检查接口。生产环境建议在 Node 前面使用 Nginx/Caddy 终止 HTTPS，并把 `/ws` 反向代理为 WebSocket；前端仍通过同源地址连接，不需要改写大厅协议。

当前项目仍然是以前端为主的可玩原型；本地联机对局已经使用服务器权威骰子、计分、回合、统一钱包和收藏同步，但仍未做账号登录、跨设备身份迁移、商店防刷策略和公网部署。`server-data/players.json` 已加入 `.gitignore`，不会随代码上传个人联机存档；服务器启动时会自动创建空存档。Three.js 与 Cannon.js 通过 CDN 加载；若运行环境阻止 CDN，页面会自动隐藏 3D canvas 并保留牌桌 UI，但不会生成 2D 骰子替代层。要做到成品级 1:1 美术还需要替换酒馆背景、角色肖像与骰子材质资源。
